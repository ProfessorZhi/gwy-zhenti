# 申论「解析状态：unknown」全量核对（2026-10-27）

## 起疑的原因

全库 1,108 份申论卷里有 612 份、952 道题在 `<details>` 里写着：

```markdown
**解析状态：unknown（来源未提供）**
```

但抽查发现，其中不少题的采集缓存（`document.json`）里明明有整段「文章分析」：带【标题的优点：…】【论述段 1 的优点：…】逐段批注的范文，两三千字。也就是说，**不是粉笔没给解析，是本库自己弄丢了**。因此对 952 道逐题做了三分类核对。

## 口径

1. **缓存位置**：按 frontmatter 的 `源试卷ID` 找 `document.json`。因为粉笔行测与申论的题号空间有重号（例如 `219` 同时是上海 2010 申论与江西 2012 行测），索引键必须带上 `subject`，并核对年份/地区，否则会把别人的解析搬过来——第一版核对就踩过这个坑，虚报 101 道「内容缺失」，严格身份匹配后全部消失。
2. **「实质解析」判据**：`explanationHtml` 去掉标签、空白，再剔除 `考点：…`、`来源：…` 与「粉笔申论页面对本题只提供解析视频入口」这类元信息后，正文 ≥ 20 字。
3. **「MD 里已经有」判据**：把源解析的正文做 8-gram 集合，与 `<details>` 块正文求覆盖率；≥ 0.5 视为正文已在（只是位置或标注错了）。

## 结果

| --- | ---: | ---: | --- | --- |
| 正文已在 MD 里，却标成 unknown | 338 | 332 | 渲染/拆分错位：文章分析落在「参考答案」区 | 把「文章分析 / 范文分析」段移回解析区，删掉误标 |
| 缓存只有考点/来源 | 45 | 15 | 粉笔页面本身没有文字解析 | 删掉误标，解析区保留「考点」「来源」 |
| 本地无采集缓存 | 569 | 267 | 未核实 | 待回粉笔逐卷核对，清单见同目录 JSON |

合计 952 = 338 + 45 + 569。本轮离线修掉 383 道，剩余 569 道挂在待核清单里。

复现：

```

  /home/fjd/tmp/shenlun-verify-20261027-round3 out.json
```

## 根因

`tools/fenbi/src/render.mjs` 的 `explanationFragment()` 只按「考点」切分解析区：只要 `explanationHtml` 里出现 `<strong>考点</strong>`，它就把考点之前的内容整段丢掉。对「参考答案说明 + 考点」这种形态这是对的（说明已在答案区），但对「文章分析 + 考点」就错了——被丢掉的正是解析正文。渲染器已改为：先认「文章分析 / 范文分析」，有就从那里起切，没有才退回「考点」；两种情况都保留考点与来源。

**发现方式**：`audit_fidelity.py` 的解析比对用的是同一条「考点」切法，所以源侧与 MD 侧一起被切掉，审计一直显示 `expl_miss = 0`——口径同错会互相掩盖。

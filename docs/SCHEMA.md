# 文档格式

一份卷 = 一个 `.md` 文件 + 它引用的图片。格式目标是：**GitHub 直接打开能读，脚本直接解析能对齐题目**。

## 文件位置与命名

```text
国考/<年份>/<科目>-<卷型>.md
省考/<地区>/<年份>/<科目>-<卷型>.md
图片/<试卷唯一标识>/...
```

- 科目：`行测` / `申论`
- 卷型：`副省级` `地市级` `行政执法` `A类` `B类` `C类` `统考` `乡镇` …
- 广州市考、深圳市考是独立考试序列，写在 `省考/广东/`、`省考/深圳/` 下，文件名带考试系列标记。
- 同一年同一科目可能有多卷，卷型必须区分，不能互相覆盖。

## frontmatter

```yaml
---
考试: "省考"
地区: "浙江"
年份: "2025"
科目: "行测"
卷型: "A类"
真题性质: "粉笔题库整理版本，未认证为官方原卷"
来源: "https://www.fenbi.com/spa/tiku/..."
源试卷ID: "77306"
采集时间: "2026-10-22T21:09:00Z"
题号口径: "采集到的来源题号，待人工与原卷核对"
校验状态: "候选；机器结构验收通过，尚未人工核验或正式入库"
---
```

| 字段 | 含义 | 机器用途 |
| --- | --- | --- |
| `考试` | 国考 / 省考 | 分类与统计 |
| `地区` | 省份、直辖市、自治区，或 `国考` | 覆盖矩阵的行 |
| `年份` | 考试年份 | 覆盖矩阵的列 |
| `科目` | 行测 / 申论 | 决定正文结构 |
| `卷型` | 原卷类别 | 同年同科目下的区分键 |
| `真题性质` | 来源可信度声明 | 防止把回忆版当官方卷 |
| `来源` | 原始 URL | 溯源 |
| `源试卷ID` | 题库内部 ID | 与 `document.json` 对齐的键 |
| `题号口径` | 题号从哪里来 | 提示编号可能不等于原卷 |
| `校验状态` | 人工/机器核验进度 | 决定能否对外宣称 |

非粉笔来源的卷另有 `命题形式`、`来源明细`、`实有题数`、`缺失原题号`、`分卷核对证据` 等字段（申论早期批次更常见）。

## 正文结构（行测）

```markdown
# 2019年国家公务员录用考试《行测》题（副省级）

<!-- gwy:overview:start -->
> **国考 · 2019 · 行测 · 副省级** ｜ 135 题 · 图片 210 处 · 答案随题折叠

| 题型模块 | 题量 | 题号 |
| --- | ---: | ---: |
| 常识判断 | 20 | 1–20 |
| … | | |
| **合计** | **135** | |

导航：[题型与作答说明](#题型与作答说明) · [题目](#题目) · [材料 1](#材料-1)
<!-- gwy:overview:end -->

> 候选采集稿。参考答案及解析来自粉笔页面，不代表官方答案……

## 题型与作答说明        ← 可选，按章节
## 题目
### 第 116 题
（题干）
A. 选项
B. 选项

<details><summary>第 116 题 · 答案与解析</summary>

**参考答案（粉笔题库参考内容）**

…

**解析**

…
</details>

## 材料 1               ← 资料分析/篇章阅读的大材料，紧跟首个引用它的题组
### 第 121 题
…
```

要点：

- **材料就近**。材料按「首个引用它的题」排序编号为 `材料 1…N`，只出现一次，插在题组前面；不再把全部材料堆在卷首。
- **引用行按需保留**。材料就在上方时省略 `关联材料：`；跨组引用或一题多材料时才写 `关联材料：材料 2、材料 3`。
- **图形题的图**跟在题干里（`![...](assets-…/xxx.png)`），不单独成段；选项各占一行。
- **表格**用原生 Markdown；公式尽量保留为图片（题库原始形式），不臆改成 LaTeX。

## 正文结构（申论）

```markdown
## 给定材料
### 材料 1
（给定资料全文）
### 材料 2
…
## 题目
### 第 1 题
（题干）
关联材料：材料 1、材料 2
作答要求：……

<details><summary>第 1 题 · 答案与解析</summary>

**参考答案（粉笔题库参考内容）**
…
**解析**
…
</details>
```

- 给定材料**全文前置**（申论是全卷共用），逐段编号。
- 题干里的 `关联材料：材料 N` 与上面的编号一一对应。
- `作答要求：` 保留字数限制、分值等，不并入题干。

## 答案区

- **默认版式：题 → 折叠答案 → 题 → 折叠答案。** 每道题后紧跟 `<details><summary>第 N 题 · 答案与解析</summary>`，默认收起，读完题就地展开。
- 渲染器（`src/render.mjs`）仍先输出卷末 `## 答案与解析`；`tools/polish_markdown.py` 再按题号搬移，题号对不上就整卷不动。
- 文案：渲染产物的答案区在卷末可作为中间态；**提交到仓库的最终格式**以上面的逐题折叠为准。
- 答案标签区分来源：
  - `**参考答案（粉笔题库参考内容）**`
  - `**参考答案（原库来源，按题目内容唯一映射保留）**`
- 解析标签同理：`**解析**` / `**解析（原库来源…）**`。
- 来源确实没给答案/解析时，写 `**答案状态：unknown（来源未提供）**`，**不留空、不编造**。
- 申论若来源只提供「考点 / 来源」元数据、没有文字解析，渲染为：

  ```markdown
  **考点**：提出对策类

  **来源**：2016年国家公务员考试申论题（副省级）

  > 粉笔对本题只提供解析视频入口（会员推广位），页面无文字解析。
  ```

## 图片

- 一律**本地相对路径**，相对于该 `.md` 所在目录：

  ```markdown
  ![](assets-fenbi-78636/68a2041f….jpg)
  <img src="../../图片/<卷名>/题目图/66.png" alt="第 66 题题图">
  ```

- 不 Base64 内联，不用外链，不做有损压缩。
- 同一张图只出现一次（题库 DOM 里答案与解析可能重复引用同一张图，渲染时去重）。
- 断链检查：`python3 tools/audit_fidelity.py --work <采集工作区>` 的 `img_broken` 应为 0。

## 采集侧 document.json

渲染的上游。两种 schema：

**标准（行测 / 新申论）**

```json
{
  "schemaVersion": 1,
  "identity": {"area": "江苏", "year": "2019", "subject": "xingce", "variant": "A类", "id": "…"},
  "source": {"url": "…", "capturedAt": "…"},
  "expected": {"materials": 3, "questions": 135},
  "materials": [{"id": "material-1", "number": 1, "contentHtml": "…"}],
  "questions": [{
    "id": "q-1", "number": 1, "contentHtml": "…",
    "options": [{"label": "A", "contentHtml": "…"}],
    "materialIds": ["material-1"],
    "answerHtml": "…", "explanationHtml": "…", "requirementsHtml": null
  }],
  "assets": [{"url": "…", "localPath": "…", "sha256": "…", "status": "downloaded"}],
  "evidence": {}, "conflicts": []
}
```

**旧申论（`shenlun-capture/`）**

```json
{"questions": [{
  "index": 1,
  "prompt": {"html": "…（注意：可能包含整页答案 DOM）"},
  "referenceAnswer": [{"title": "参考答案", "html": "…"}],
  "otherSections": [{"title": "解析", "html": "…"}]
}]}
```

两种格式在审计脚本里会被统一成 `{number, contentHtml, options, answerHtml, explanationHtml}` 再比对。旧格式的 `prompt.html` 含答案 DOM，是「MD 比源短」的已知原因。

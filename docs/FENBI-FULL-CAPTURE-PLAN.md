### 实际命令（在 Dell A6000 上执行，不经东京）

默认只读、不写题文；`--write` 才写到本机被 git 忽略的 `work/fenbi/batch-ingest/`，不修改正式题库：

```bash
cd /path/to/gwy-zhenti/tools/fenbi
node src/batch-ingest.mjs --repo-root /path/to/gwy-zhenti --source-root /path/to/owner/work/fenbi/papers
node src/batch-ingest.mjs --repo-root /path/to/gwy-zhenti --source-root /path/to/owner/work/fenbi/papers --write
```

以上输出每卷一行 metadata-only 回执（A/C、题数、继承数、未知答案数、SHA），不是长篇审计报告。`--write` 会在独立候选目录保存 `paper.md`、源图片和旧版 `legacy-original.md`（若有），同 SHA 的重复执行可幂等复用；不同内容拒绝覆盖。

正式集成只能在**非 main 的独立 Git 工作树**中完成，并必须提供 Dell 本地 0600 `rightsFile`：逐来源 ID 记录用户 2026-10-19 的私人存储批准；如另有来源版权许可，也一并记录。

```bash
node src/batch-promote.mjs --candidate-dir /path/to/work/fenbi/batch-ingest/<卷> --repo-root /path/to/integration-worktree --rights-file /path/to/local-rights.json
# 上一条只预检；必须获授权时才加 --apply。
# 要替换已经存在的卷还须另加 --allow-replace，并核对旧文件 SHA。
```

权限 JSON 示例结构为 `{"schemaVersion":1,"allowGitHubStorage":true,"evidence":"用户私有存储批准的原句/日期（本地引用；不代表第三方许可证）","sourceIds":["已观察来源ID"]}`，**示例本身不是授权；不得伪造第三方许可证或权利人身份**。没有用户私有存储批准，或存在明确版权/网站条款禁止时，保留在 A6000 本地候选，不可自动提交第三方题文或解析。



```text
① 抓取（1 个 Claude Code，2–3 个标签页）
      ↓ 本地缓存 + 一行回执
② 生成（2–3 个 Claude Code，按卷认领）
      按第二节规则生成或覆盖 Markdown，复制图片
      ↓
③ 自动检查（同一个 Claude Code 当场跑，不另开一轮）
      ↓ 通过 = A；不过 = C，写明原因，继续下一卷
④ 集成（1 个 Claude Code，每天一次）
      把当天所有 A 卷合进集成分支，更新台账和看板
      ↓
   用户每周审一次，合进 main
```

QA 不逐卷复核，每天**抽 5 卷**，尽可能覆盖图片、题序变化、占位继承、旧答案映射和纯新卷五类；若抽中系统性错误，暂停受影响规则的集成，修复后仅重跑相关批次。

## 五、自动检查（唯一的检查，跑一次就算）

由 Batch Ingest 在同一遍生成中完成；`batch-promote` 只对结构 A 做发布必要的权限、哈希和 manifest 前置检查。粉笔来源暂未显示答案/解析时标 unknown，不能据此生成假答案。


- 题位守恒：粉笔有效题位 + 按唯一题目身份继承的原库非占位题位 + 明确列出的真实缺位 = 目标卷声明题位；输出题号连续，不用删掉占位后反推总量
- 每题有题干和选项（申论有材料和问题）
- 正文里引用的图片都存在，并且 SHA 与缓存一致
- 没有残留的"正在征集"等占位文字
- 答案与题目的稳定身份一一对应，粉笔异序需先重建映射；无独立答案或解析的题标 unknown，不凭题号/选项位置猜
- 已有的 G1–G6 闸门通过

不在这一节里的检查都不做。

## 七、抓取速度与自动停止

- 1 个浏览器上下文（持久 profile），1 个采集 Owner，**运行时开 3 个标签页**（用户 2026-10-19 选定，配合 30 秒停留，约 120 卷/小时）。只有正常可读且观察到可复现 URL 的练习才允许入队，不通过增加账号/进程放大并发。
- 对同一站点的**导航**使用所有 Page 共享的最小 2.5 秒间隔（历史配置低于此值也强制抬到 2.5 秒），出现限流信号自动退避。页面的其他资源请求并非全部都经过此导航闸门，不宣称总 HTTP 请求频率受同一个数字限制。

| 信号 | 动作 |
|---|---|
| 验证码、登录失效 | 立即停，通知用户 |
| 403 / 429 | 退避；一小时内 3 次就停，通知用户 |
| 会员/付费提示 | 跳过，记入会员卷清单，继续下一卷 |
| 打开的不是目标卷 | 记 `blocked`，继续下一卷 |
| 连续 3 卷失败 | 停，通知用户 |

每卷流程：开练习 → 停留约 30 秒 → **交白卷**（不作答）→ 读解析页（题干、选项、材料、图片、答案、解析一次读全）。
- 只放行"交卷"这一个写操作，其他写操作照常拦截；同一卷只交一次，不作答、不刷分。
- 已缓存但未交卷的卷（"未完成"练习）直接交卷、补读解析页，不重新开练习。
- 不购买、不绕验证。

## 八、防止空转的硬规则（所有 Claude Code 必须遵守）

1. **产出只有三种**：抓取缓存和回执、改过的 Markdown、台账里的一行。**不写报告，不写审计文档，不开 PR**（集成角色那一个集成 PR 除外）。
2. **工具冻结**：现有采集、队列和闸门代码够用。只有在它挡住进度时才改，而且只改那一处，改完跑一遍相关测试就继续。
3. **不重复验证**：一卷到了 A，正文不变就不再检查。不复核别人的复核。
4. **限时**：每张任务卡 40 分钟内完成；到时先停止领取新任务、落原子检查点并释放租约，完成安全退出后记 `blocked/timebox` 和一行原因。不在 Markdown/图片写入中途强杀进程。
5. **遇到不确定的情况按第二节规则直接处理**，不要停下来写分析。
6. **每天的成绩只看台账**：当天新增的已抓、A、C 数。连续一天没有增长，GPT 调整派工，而不是让 agent 加做检查。

### A6000 上的有界策略

- **Collector**：始终 1 个进程/1 个持久登录态；新配置下 `capture --all` 默认 2 个 Page，支持显式 `--concurrency 1|2|3`。Page 共用会话、可复现 URL 检查、同域导航节流和停止标记；3 Page 是上限，不能开启多个同账号 Profile 或多份 Owner 规避限制。

- **风控/成本**：验证码、账户异常、403/429 与平台限制遵照第七节停止/退避；观察到限流或 3 Page 无收益就退回 2 或 1 Page，不绕过访问限制。没有真实证据的付费内容不入队。

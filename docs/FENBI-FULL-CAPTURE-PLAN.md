# 粉笔全量抓取落地方案（2026-10-18 定稿）

GPT 照本文件给 A6000 上的 Claude Code 派任务。总控进度只在 Issue #84 更新。

## 一、用户已确认的决定

| # | 决定 |
|---|---|
| 1 | 接受账号风险，**尽快抓**：不设每日上限，只靠自动退避控速 |
| 2 | **先抓免费卷**；会员卷登记在单独清单里，是否开会员由用户另定 |
| 3 | **先做完重点区**，再处理其他地区 |
| 4 | **信任粉笔质量**：粉笔有、本库没有的卷直接用粉笔补入 |
| 5 | 仓库**改为私有**，粉笔解析一并收录 |

重点区：国考、浙江、江苏、上海、北京、天津、广东、广州、深圳、福建。

## 二、核心规则：粉笔优先

用户已决定信任粉笔，所以**不再逐题人工裁决差异**。重点区的规则：

| 情况 | 处理 |
|---|---|
| 本库没有这卷 | 用粉笔整卷生成 Markdown |
| 本库有，粉笔内容完整 | **以粉笔为准重写正文**（题干、选项、材料、图片、答案、解析），题序也按粉笔 |
| 本库有，粉笔某题是"正在征集"等占位 | 这一题保留本库原文，标 `本题来源: 原库` |
| 本库有、粉笔没有的卷 | 保持原样，等级记为 B，不作处理 |
| 本库已有的其他来源答案或范文 | 保留在原位，标明来源，不删 |

这样核对不再产生待人工复核的积压：差异直接按规则处理，只记一行"改了什么"。

## 三、质量等级

| 等级 | 条件 |
|---|---|
| **A** | 按粉笔生成或重写，并且通过第五节的自动检查 |
| **B** | 粉笔没有，只有原库内容 |
| **C** | 自动检查没过；必须写明哪几题、什么问题 |

目标：重点区里粉笔有的卷全部 A；C 级清零。

## 四、流水线（只有 4 步）

```text
① 抓取（1 个 Claude Code，2–3 个标签页）
      ↓ 本地缓存 + 一行回执
② 生成（2–3 个 Claude Code，按卷认领）
      按第二节规则生成或覆盖 Markdown，复制图片
      ↓
③ 自动检查（同一个 Claude Code 当场跑，不另开一轮）
      ↓ 通过 = A；不过 = C，写明原因，继续下一卷
④ 集成（1 个 Claude Code，每天一次）
      把当天所有 A 卷合进集成分支，更新台账和看板
      ↓
   用户每周审一次，合进 main
```

QA 不逐卷复核，每天**抽 5 卷**看一遍。抽查发现系统性问题，就修改生成规则，再整批重跑。

## 五、自动检查（唯一的检查，跑一次就算）

- 题数 = 粉笔题位数（占位题除外）；题号连续
- 每题有题干和选项（申论有材料和问题）
- 正文里引用的图片都存在，并且 SHA 与缓存一致
- 没有残留的"正在征集"等占位文字
- 答案题号与题目题号一一对应
- 已有的 G1–G6 闸门通过

不在这一节里的检查都不做。

## 六、抓取顺序

1. **P0 目录**：浏览深圳、福建、广州的粉笔目录，与 `catalog/manifest.jsonl` 对上身份，生成抓取清单（只做一次）。
2. 已能读的 10 份：不用开新练习，直接进入生成步骤。
3. 重点区里本库缺的卷。
4. 本库有缺题的 5 卷：北京2026行测、江苏2026行测A、广东2020县级、江苏2024行测A、浙江2020行测A。
5. 重点区其余免费卷。
6. 其他地区：同样流程。
7. 会员卷：等用户决定。

不单独做 20 套试点，直接开抓：前 20 套就是试点，统计数据从回执里直接读。

## 七、抓取速度与自动停止

- 1 个浏览器上下文（持久 profile），最多 3 个标签页；不用多账号。
- 请求间隔 2.5 秒起步；出现风控信号就自动加倍。

| 信号 | 动作 |
|---|---|
| 验证码、登录失效 | 立即停，通知用户 |
| 403 / 429 | 退避；一小时内 3 次就停，通知用户 |
| 会员/付费提示 | 跳过，记入会员卷清单，继续下一卷 |
| 打开的不是目标卷 | 记 `blocked`，继续下一卷 |
| 连续 3 卷失败 | 停，通知用户 |

只读题：不作答、不交卷、不购买、不绕验证。

## 八、防止空转的硬规则（所有 Claude Code 必须遵守）

1. **产出只有三种**：抓取缓存和回执、改过的 Markdown、台账里的一行。**不写报告，不写审计文档，不开 PR**（集成角色那一个集成 PR 除外）。
2. **工具冻结**：现有采集、队列和闸门代码够用。只有在它挡住进度时才改，而且只改那一处，改完跑一遍相关测试就继续。
3. **不重复验证**：一卷到了 A，正文不变就不再检查。不复核别人的复核。
4. **限时**：每张任务卡 40 分钟内完成；做不完就把这卷记为 `blocked`，写一行原因，领下一张。不在同一个问题上反复重试。
5. **遇到不确定的情况按第二节规则直接处理**，不要停下来写分析。
6. **每天的成绩只看台账**：当天新增的已抓、A、C 数。连续一天没有增长，GPT 调整派工，而不是让 agent 加做检查。

## 九、角色与数量（A6000）

| 角色 | 数量 | 做什么 |
|---|---:|---|
| 抓取 | 1 | 浏览器抓卷，写本地缓存和回执 |
| 生成 | 2–3 | 按卷认领：生成 Markdown + 自动检查 + 定 A/C |
| 集成 | 1 | 每天合并、更新台账和看板、抽查 5 卷 |

一份卷同一时间只能被一个 Claude Code 认领；只有集成角色能合并。合并前确认仓库 `private: true`，否则停止。

## 二、质量等级（每卷一个，记在台账里）

| 等级 | 条件 |
|---|---|
| **A 已验收** | 身份和卷型正确；题号齐全且对应原卷；题干、选项、材料与粉笔一致（或两个独立来源一致）；图片逐张比对；答案有出处；没有占位题 |
| **B-粉笔** | 本库原来没有，按决定 4 以粉笔为唯一来源补入；内容完整、通过闸门，但没有第二来源 |
| **B 单源** | 内容完整，只有一个非粉笔来源，未交叉核对 |
| **C 有问题** | 缺题、缺图、内容不一致、题序未证实；必须列出问题题号 |

- 重点区目标：全部 A。B-粉笔 卷如果之后找到第二来源，就升为 A。
- 粉笔采集的**原始数据只留在 A6000 本地**，不进 Git。
- 粉笔补入的卷，入库内容只取题干、选项、材料、图片和答案，**不取粉笔自己写的解析**；frontmatter 标注 `来源: 粉笔`。

## 三、阶段

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| P0 目录补全 | 浏览深圳、福建、广州的粉笔目录（只看目录），再复核已浏览的 7 个地区；每条目录与 `catalog/manifest.jsonl` 对上身份 | 得到重点区完整清单，每条标为：本库已有 / 本库缺 / 只有粉笔有 / 会员卷 |
| P1 试点 | 抓 20 套：先抓本库缺的，再抓高风险的 | 测出每套耗时、出错率、风控信号，确定稳定速度 |
| P2 重点区全量（免费卷） | 按第四节的顺序抓完所有免费卷 | 重点区免费卷全部 `capture_ready` |
| P3 并行核对 | 每抓完一卷立即离线核对，不等全部抓完 | 每题恰好一个类别；不一致的转第二来源判定 |
| P4 修复与入库 | 修 Markdown → QA 定等级 → 每天合一班进集成分支 → 每周用户审一次进 main | 重点区缺卷 0、C 级 0 |
| P5 其他地区核对 | 对其他地区重复 P0–P4，只核对已收卷 | 其他地区已收卷都有等级 |
| P6 粉笔补缺 | 粉笔有、本库没有的卷，以 B-粉笔 补入（重点区优先，补缺不必等到 P5 做完） | 粉笔目录里的卷全部收录 |
| P7 会员卷 | 用户决定开会员后，按同样流程抓取会员卷 | — |

4. 重点区其余卷

## 五、速度与自动停止

- 1 个采集 Claude Code、1 个浏览器上下文（持久 profile），最多 3 个标签页。不用多账号，不同时在多处登录。
- 同一站点共享节流：请求间隔从 2.5 秒起步。连续顺利时不再放慢；一出现风控信号就自动加倍间隔。
- 不设每日上限。

| 信号 | 动作 |
|---|---|
| 验证码、登录失效 | **立即停**，报告用户，等人工处理 |
| 403 / 429 | 指数退避；同一小时内出现 3 次就停下报告 |
| 付费/会员提示 | 跳过该卷，记为 `member_only`，继续下一卷 |
| 落地页不是目标卷 | 该卷标 `blocked`，继续下一卷 |
| 连续 3 卷失败 | 停下报告 |

只读题：不作答、不交卷、不购买、不绕过验证。

## 六、角色与并发（A6000）

| 角色 | 数量 | 能做 | 不能做 |
|---|---:|---|---|

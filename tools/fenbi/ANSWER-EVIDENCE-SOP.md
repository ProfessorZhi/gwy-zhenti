# 实站答案解析取证 SOP

适用范围：`tools/fenbi` 只读采集框架在**真实粉笔站点**上核对某一份试卷的参考答案与解析。
本文只规定取证与记录方式，不授权任何写操作，也不放宽完整性闸门。

前置：浏览器安装、专用配置与登录属于**独立 lane**，本 SOP 不代管。本 lane 不自带 Chrome/Edge 时，
只能执行下面的离线部分（第 5 步起），实站步骤留给持登录配置的执行者。

## 0. 不可越过的边界

- 只观察**实际发生**的只读响应和当前页面已渲染的只读内容；不枚举接口、不扫目录ID、不拼接猜测的URL。
- 不交卷、不开始新练习、不购买、不做支付；**不绕过验证码、人机验证或付费/会员墙**。看到限制就记录并停止。
- 不把"按钮可见"当作"答案可见"；不采未授权内容；不把人工记忆或第三方资料写成实站观察结果。
- 不向协作 Agent 传递验证码、密码、Cookie、账号资料或带凭据的URL。

## 1. 明确取证目标

先写清被核对的**单卷身份**：源试卷ID、标题、年份、地区、卷型、科目，以及对应的库内正式卷路径与其当前 SHA256。
一次只做一卷；跨卷混采会让答案与题号失去归属。

## 2. 确认当前视图是否真的暴露答案解析

按顺序观察，任何一步不成立就停在该步，不要"想办法看到"：

1. 打开该卷既有练习/题本页，**只读**观察。
2. 记录答案槽与解析槽**实际渲染到的内容**。出现下列任一情况即判定为**未暴露**：
   - 空、占位符（`暂无解析`、`待补充`、`TODO`）；
   - 访问类提示（`登录后可查看`、`开通会员后方可查看`、`暂无权限查看`…）；
   - 只有链接、提纲、"查看解析"入口而无正文。
3. 未暴露时：**整卷答案解析保持 `unknown`**，在报告中写明"当前练习视图未展示"，并记录是否为此产生过任何写操作（应为 0）。不要为了让页面显示答案而交卷、购买或切换账号。

## 3. 允许的采集途径（按优先级）

1. **只读响应**：页面实际发出的 `tiku.fenbi.com/api/{xingce,shenlun}/...` 只读 JSON。答案与解析分开保存，
   异步先到的答案按**源题ID**关联；关联不上就保持 `unmatched-answer`，缺关联不算完成。
2. **复放已观察URL**：仅限本配置已登记、且校验通过（域名、参数、状态、JSON类型、体积）的完整只读URL；
   不跟随重定向、不新建练习。
3. **DOM 规范化**：当前仅 `fenbi-xingce-v1` 适配器读取行测题面，**不读答案，不从选中状态或CSS猜答案**。
4. **人工证据**：以上都拿不到、且人工在已授权页面上确实看到时，用 `manualEvidence` 记录（见第 6 步）。

## 4. 必须落盘的证据

| 证据 | 要求 |
| --- | --- |
| 源身份 | 源试卷ID + 实际观察到的页面URL（经 `publicUrl` 剥离查询参数） |
| 答案来源 | 响应URL或人工观察方式；写入 `evidence`，不写原始响应与请求头 |
| 源题ID关联 | 每题答案绑定的源题ID；未绑定项保留为 `unmatched-answer` 证据 |
| 答案/解析正文 | 只保存**实际观察到的**正文；空与提示语保持空，不补、不改写、不翻译、不"补全" |
| 逐题对齐 | `align` 报告（含 `verification` 块）与其 `verdict` |
| 访问事件 | 验证码、401/403、付费/会员提示，均按 blocked/partial 记录 |
| 采集指纹 | 配置指纹、文档 SHA256、任务指纹（checkpoint 已含） |

报告只保留身份、数量、状态与摘要，不保留账号资料、会话凭据和题目正文以外的个人数据。

## 5. 判定口径

- 逐题维度与卷级检查都取 `verified` / `partial` / `conflicting` / `unknown` / `not_applicable`（定义见 README）。
- **只有 `verdict === "verified"` 才能说"该卷答案与解析已核验"**；`align` 此时返回 0，其余一律返回 2。
- `not_applicable` 必须与结论同时报告，不能省略成"全部通过"。例如行测DOM命名空间与库内数字qid不同，
  逐题ID比较本就无从进行，这既不是通过也不是缺口。
- 公式图与文字的等价（如 `90°` 对公式图）**单列人工复核记录**，写明复核方式与未改正式卷，不并入严格统计。
- 机器 `verified` 只表示"框架定义的结构与观察一致性通过"，**不等于官方原卷认证、评分正确或全站覆盖**。
- 未暴露的答案与解析，结论只能是"未核验"，不能是"原库答案正确"或"原库答案错误"。

## 6. 人工证据的写法

框架读不到、人工确实看到时，写进文档的 `manualEvidence`（**不写进正式卷，不写进对齐报告**）：

```json
{"manualEvidence": [
  {"dimension": "answer", "questionId": "OBSERVED_SOURCE_QUESTION_ID", "value": "人工实际看到的内容",
   "observedAt": "2026-10-17T00:00:00.000Z", "observedUrl": "OBSERVED_PAGE_URL",
   "method": "operator-screenshot-read", "operator": "OPERATOR_LABEL"}
]}
```

- 绑定必须唯一落到一道**已被自动匹配**的采到题目；否则记为 `unbound`/`unmatched-source`，不生效。
- 缺 `value`/`observedAt`/`method` 记为 `incomplete`。
- 人工记录只出现在 `dimension.manual`，**不并入自动计数，也不能单独把整卷变成通过**。
- 报告只保留人工内容的 SHA256 与长度，不落正文；URL 按 `publicUrl` 规则剥离凭据参数。
- 人工证据是**补充说明**，不能替代第 3 步的只读采集；两者冲突时以自动观察为准并复核。

## 7. 交付时必须同时报告

卷身份与来源、答案解析是 `verified` 还是未核验及原因、`verification.unverified` 与 `notApplicable`、
人工证据条目及其绑定状态、执行过的写操作次数（应为 0）、未解决项与登录依赖。
**不得**把未核验写成通过，不得用合成测试结果代替实站证据，不得声称未实际运行的 CI 为绿色。
